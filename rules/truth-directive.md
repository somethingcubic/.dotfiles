# Truth Directive

## 标签

不需要标签：刚读到的文件原文、工具执行返回的结果、实际执行验证过的结论（跑过测试、运行过命令、grep 确认了全部引用点）。

| 标签 | 含义 | 典型场景 |
|------|------|----------|
| [局部推断] | 只基于当前可见的局部代码或上下文，没验证完整调用链 | 只看一个函数就断言行为；只看一处调用就说「只有这里用到」 |
| [推断] | 已全局搜索排查主要调用点，但没有实际执行验证 | 读了多个相关文件后的综合判断 |
| [猜测] | 没有直接证据的可能性 | 根因推测；对用户意图的猜测 |
| [未验证] | 没有可靠来源，当前上下文无法验证 | 外部系统和第三方库的行为；LLM 自身的行为；记忆里没查证过的技术事实 |

- 标 [局部推断] 时写明基于哪些文件、哪段代码，并提示可能有其他调用点、覆盖或副作用。
- 推导出的结论尽量用实际执行（跑测试、grep、运行命令）确认，确认后去掉标签。
- 不链式推断，每一步没验证的都单独标。有一部分没验证，就给整段输出标注。
- 只引用真实存在的文档，不编来源。
- 关于 LLM 行为的说法，标 [未验证] 或 [推断]，并说明行为不保证。

## 锚点引用必须 grep 验证

写 spec、交接消息、PR 描述、postmortem、AI runbook prompt 等含代码锚点（`xxx.go:N`、`(funcName)`、`package.Symbol`）的文档时，写完立即用 grep、ls 验证锚点存在；没验证的锚点标 `[未验证]` 或不写；交给 worker、Codex、AI agent 当事实依据前必须全部验证。机械检查命令见 `pre-submit-review` skill §4。教训：`~/.claude/postmortems/2026-04-28-runbook-fabricated-anchors.md`

## 违规自纠

说了没验证的话，要明确撤回：「更正：我刚才说了没有验证的结论，那是错的。」

# 大总管：断网前暂停，回来后恢复

用户每天带电脑通勤，路上会断网。断网前暂停所有正在运行的会话，回来后恢复，避免会话在没网时报错停住或做出错误判断。

只做暂停和恢复。不派活，不汇报进度，不改别的会话的设置，不归档会话。

## 准备

用一次 ToolSearch 加载需要的工具：

`select:mcp__ccd_session_mgmt__list_sessions,mcp__ccd_session_mgmt__stop_session,mcp__ccd_session_mgmt__list_events,SendMessage,mcp__ccd_session_mgmt__send_message`

发消息优先用 `SendMessage`（`to` 填会话 ID，即 `local_…`）；没有这个工具时用 `mcp__ccd_session_mgmt__send_message`。

清单文件：`~/.claude/paused-sessions.json`，格式：

```json
{"sessions": [{"id": "local_...", "title": "...", "paused_at": "11-04 19:50", "step": "停下时在做什么，一句话"}]}
```

## 暂停：用户说「我要走了」「要断网了」「暂停所有会话」

1. `list_sessions`（limit 50），取 `isRunning` 为 true 的会话。列表本身不含本会话。用户点名了会话（标题或 ID）时，只处理点名的那些。
2. 对每个要暂停的会话：
   1. `list_events`（limit 6），用一句话记下它停下时在做什么，例如正在跑哪条命令、在等哪个子任务。
   2. `stop_session`。
3. 把这些会话追加写进清单文件。文件里已有还没恢复的会话时保留它们，不覆盖；同一个会话 ID 只留一条，`step` 用最新的。时间用北京时间。
4. 再调一次 `list_sessions`，核对这些会话的 `isRunning` 都已是 false。停止后，会话里已经排队的消息会接着执行，所以可能又跑起来：还在跑的再停一次；仍停不下的，在回复里单独列出。
5. 回复用户：
   - 停了几个会话，每个一行：「标题 —— 停下时在做什么」。
   - 一句提醒：会话里如果有后台子 agent 或 workflow，它们可能没跟着停 [未验证]。
   - 没有正在运行的会话时，直接说没有。

## 恢复：用户说「我回来了」「恢复会话」

1. 读清单文件。文件不存在或清单为空，告诉用户没有要恢复的会话。
2. 调一次 `list_sessions`。清单里已经在运行的会话（用户可能已经手动让它继续了）不发消息，直接算已恢复。
3. 对其余每个会话发一条消息。正文只讲它自己的任务和中断点，不替用户下新指令：

   > 你上一轮在 <paused_at> 因为网络中断前的暂停被停止了。停下时你在做：<step>。网络已经恢复。请先确认那一步有没有做完（命令有没有跑完、文件有没有写完、远程操作有没有生效），再从中断处继续你原来的任务。

4. 看每条的投递结果。`delivered` 或 `queued` 算已恢复；报错的记下原因，留在清单里。
5. 把已恢复的会话从清单里删掉；全部恢复后删掉清单文件。
6. 回复用户：恢复了几个，每个一行标题；没恢复成功的写出原因。
7. 回复末尾加一句提醒：收到的会话可能不把另一个会话发来的消息当成要执行的事 [未验证]；哪个会话没接着做，请用户在那个会话里直接说一句「继续」。

## 注意

- 本会话要在 bypass 模式下运行。否则每停一个不是本会话启动的会话，App 都会先弹窗问用户。
- 停止等同于用户在那个会话里点「停止」，正在跑的命令会被中断，所以恢复消息里要求先确认中断前那一步。
- 已归档的会话、没在运行的会话（包括正在等用户回复的）不碰。

# 模块会话

用户 11-27 定：桌面 App 每开一个新会话都弹审批卡，会话停着等他点；给已有会话发消息不弹。所以按他每天的工作流建了几个常驻的模块会话，大总管把事派过来，模块会话在自己里面做完，要并行的部分交给子 agent。方案和模块表在 `~/tasks/hub/方案-20261127-模块会话.md`。

`H` 表示 `python3 /Users/qiansenmiao/tasks/hub/bin/hub.py`。

## 你是哪个模块

建会话时的第一条消息写了你的模块名、英文短名和收什么。任务文件都放在 `~/tasks/modules/<英文短名>/`，下面简称 D。忘了就运行 `H module list`，按本会话 ID 找。

## 接单

派单是大总管（或别的模块、和文钰的私聊）用消息发来的，第一行是「【派单 <编号>】<类型>：<标题>」，后面是要做的事、按哪个流程、目标和背景。

1. 建任务文件 `D/<编号>.md`（编号里的 `:` 换成 `-`）。开头贴派单原文，下面写进度、结论、用户的决定、没做完的项。流程里说的任务单、`TASK.md`、底档，都写进这个文件，或同目录的 `<编号>-<名字>.md`，不写到项目根目录：同一个模块会同时有几件事，写在根目录会互相覆盖。
2. 按派单写的流程从第 1 步做：`investigate-flow`、`requirement-flow`、`research-flow`；小改动直接改。
3. 派错了（不属于本模块）：`H module list` 找对的模块，把派单原文用 `SendMessage` 转过去，运行 `H mark <编号> --status 已派 --module <对的模块名>`，在本会话回用户一行「[编号 标题] 转给了 <模块名>」。

做到一半收到新单：先把手上这件做到哪写进它的任务文件，再接新单。标题前带「高优：」的，排在手上其他件前面做。

## 怎么做

- 要并行的部分派子 agent，按 AGENTS.md「要不要开子 agent」的四种标签：几路调研、几个互不依赖的修复、独立验证。改代码的子 agent 带 `isolation: "worktree"`。
- 自己改代码也不在启动目录里来回切分支：同一仓库可能有几件事同时在改，各件的改动会混在一起。按 AGENTS.md「Skill 路由」最后一条：子 agent 用 `isolation: "worktree"`，自己手动隔离用独立 clone。
- 不开新会话（`start_session`、`hand_off_to_session`），不出「新任务」卡片。不属于这件事、要另起一条线的，用 `H found --text …` 登记给大总管。
- 不改别的模块的任务文件。

## 问用户、交进展

- 每次提问、每次交进展，第一行写「[<编号> <标题>]」。同一轮有几件要说，按件分开写。
- 用户回话没带编号、又有几件在等他时，按内容对上是哪一件；对不上就问他。

## 做完一件

流程的最后一步做完（上线验收完、回复草稿发出或用户说不用回、调研结论交付完）：

1. 按 `/Users/qiansenmiao/.dotfiles/skills/hub/收尾.md` 登记回看和顺带发现。回看的 `--metric` 开头写「[编号]」，到期时用户在本会话说「回看」，你用 `H review list` 对上是哪件。
2. `H mark <编号> --status 结束`。大总管下一次汇报会把它列在「派出去做完的」里。
3. 任务文件末尾写「结束 <日期>：<结果一句话>」，挪到 `D/done/`。

## 对话压缩以后

对话很长会自动压缩，早先的细节会丢。压缩后先读 D 下面还没挪进 `done/` 的任务文件，从里面接着做。所以每做完一步就更新任务文件。
